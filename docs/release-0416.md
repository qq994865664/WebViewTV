# WebView电视 0.4.16

针对 realme GT5 / Android16 / WebView153 上广东台无法起播的反馈，修正启动确认和过早替换播放器的逻辑，并补齐失败前的诊断。**手机上的具体失败根因仍未确认，需覆盖安装回测。**

## 修改

- 广东台不再执行一次 click 就标记启动完成。确认网站已接收启动、视频地址已绑定后继续播放器初始化；未确认时最多点击三次，间隔至少700ms。真正播放成功仍以视频帧/播放时钟为准。
- 广东台不再因三秒未起播就拆掉原生播放器；慢启动继续遵循用户设置的超时。只有原生媒体明确报错时才尝试一次兼容播放，避免在手机上提前中断仍在加载的播放器。
- HLS 失败时，先保存原生媒体错误、兼容播放器错误类型和细节、HTTP 状态、失败阶段、数据接收情况，再销毁引擎。避免只看到销毁后的 `error:0`、空域名、零尺寸。
- 根据已知错误显示“直播数据请求失败”“直播源拒绝访问”“直播媒体处理失败”等原因，并记录 play() 拒绝名称。HTTP 状态未知时保留未知，不据此猜测 CORS 或编码原因。
- 保留超时切源、菜单、手势、节目单及央视时段限制提示。诊断仅手动复制，不自动上传，不包含签名地址查询参数、cookies 或错误原文。

## 已知证据与验证

用户提供的 0.4.15 诊断证明页面注入和全屏已完成、HLS 兼容尝试失败，但具体错误在销毁时丢失。手机浏览器手动点击可以播放，不能直接等同于 App WebView 的播放条件，也不能据旧 `preClick:true` 判断网站已真正接受点击。

- 81 项 MuMu Android15 播放回归断言通过，包含新错误提示、旧标识隔离及原生诊断保留。
- MuMu 真实来源回测：广东新闻 `/45`、广东卫视的 m.gdtv.cn 来源均正常出画1280×720且未触发兼容替换；广东卫视央视频备用源正常出画1920×1080。正式包已覆盖安装。
- 46 项 HLS 恢复、11 项广东台启动、27 项网站兼容、56 项媒体健康检查断言通过。
- Edge144 使用手机UA进行 `/tvChannelDetail/45` 对照，正常出画1280×720；这不是 Android153 内核测试。
- 在同一真实流上模拟 HTTP403，新诊断保存 `networkError / manifestLoadError / httpStatus:403` 及替换前原生错误，播放器销毁后仍可读取。此测试不代表手机实际收到403。
- 构建资源与正式 v3 签名校验通过。版本0.4.16 / code24，最低Android9，ARMv8兼容通用包与ARMv7盒子包字节相同。

请优先回测「广东新闻」`/45`、广东卫视和广东珠江的 m.gdtv.cn 来源。仍失败时，使用「菜单 → 更多 → 来源详情 → 复制播放诊断」发回新版完整文本，重点查看 `media.startup`、`media.hls.native`、`media.hls.error` 和 `playError`。
