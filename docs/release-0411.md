# WebView电视 0.4.11

起播进度改为真实状态优先，停止长期显示缺乏依据的百分比，播放中卡顿单独显示缓冲状态。

## 加载反馈

- 已观察到网页或视频进展时显示 `正在加载...X%`。网页完成仍只表示网页阶段，不代表视频下载完成。
- 连续约三秒没有新进展时，隐藏数字并使用流动进度条，显示“正在连接直播源…”或“正在等待直播画面…”。收到新的有效视频状态、增加的缓冲数据或受控 HLS 网络数据后恢复估算。
- 相同的阶段、缓冲长度或累计字节重复上报不会重置无进展计时。暂停期间冻结估算和无进展判定。
- 播放中卡顿使用“正在缓冲…”和不定进度条，不再显示起播百分比；保留短缓冲防抖及切源倒计时。
- 数据和估算均不会延长设置中的直播源超时，保留 5/10/15/30 秒、关闭时 18 秒及单轮最多 60 秒限制。实际出画及全屏就绪后立即收起加载提示。

## 状态检测与历史

媒体事件优先检测元数据、当前帧、缓冲增长和播放器替换。DOM 变化合并处理，起播前最多十秒使用 250 毫秒兼容采样，稳定播放或超过十秒后降至 1.5 秒。支持的系统 WebView使用真实视频帧回调；旧版保留媒体时钟兼容判断。替换视频及页面退出时清理事件、观察者、帧回调和定时器，拒绝旧页面或旧视频的迟到回调。

每个来源在本机保留最近八次成功出画的分阶段耗时：网页完成、播放器准备、视频数据就绪及最终画面显示。未知阶段使用缺失标记，不能伪造样本；根据各阶段有效记录的中位数辅助当前阶段估算。旧版整体耗时记录不会当成分阶段数据使用。失败、后台暂停时的完成事件不写入新样本。

Hoolo 的一次 HLS 兼容恢复额外观察播放列表、视频分片和缓冲完成事件中的真实接收字节，重复事件去重并以 500 毫秒合并报告。它仅表明网络活动，不证明视频可播放；不接管其他网站的播放器。实例失败或销毁、页面退出后停止报告。

百分比仍是起播准备程度的估算，网页直播通常无法提供整个起播流程的精确下载总量。对于无法读取的视频状态，使用明确的等待状态与超时倒计时。

## 安装

版本 0.4.11 / versionCode 19，最低 Android9（API28），沿用正式签名支持覆盖升级。发布 ARMv8 兼容通用 APK、字节相同的 ARMv7 盒子包及 SHA-256 校验文件。菜单、分组行高、节目预览与手势风格沿用 0.4.10。

运行验证使用 MuMu Android15；Android9 ARMv7 实机仍待验证。频道和 EPG 数据源不变。
