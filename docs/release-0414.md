# WebView电视 0.4.14

针对手机端在连接直播源阶段超时的问题补充兼容恢复与诊断。**realme GT5 暂未连接调试，手机实际故障根因和修复效果仍需回测确认。**

## 修改

- 播放器脚本初始化失败后每文档最多尝试三次；成功初始化才写入成功标记，换台后旧重试失效。
- 广东台 m.gdtv.cn 的原生 HLS 起播出现媒体错误，或网站已提供地址但三秒仍未就绪时，尝试一次 HLS.js 兼容播放。保留网站给出的完整地址；正常播放、已有 MSE 播放器和未提供地址的频道不替换。兼容失败不循环，原有 5/10/15/30 秒切源设置及整轮上限继续生效。
- 广东台播放按钮识别兼容网站已写入 video/source、但 Vue 状态不可访问的情况，空地址时不提前点击。
- 北京台 btime.com 页面明确要求登录时，显示“该直播源要求网页登录”，并按设置超时切源。不会绕过网站登录，也不承诺该源无需登录即可恢复播放。
- 网页连接、适配失败等已知错误直接显示在加载/失败卡上。
- 菜单「更多 → 来源详情 → 复制播放诊断」提供当前设备、Android/WebView 版本、来源路径、注入状态、媒体状态及错误码，同时附最近一次超时记录。诊断在本机手动复制，不自动上传，不含 cookies、网页正文或签名地址查询参数。

深蓝配色、分组行高、底部按钮、节目预览、上下翻页及出画后的五秒信息面板保持 0.4.13 的设计。

## 验证

- MuMu Android15 / WebView 110：广东卫视和广东珠江 m.gdtv.cn 正常出画，未触发兼容替换；北京卫视、广东卫视的央视频来源正常出画；btime.com 无视频且显示登录限制，新版准确提示。
- 独立 Edge144 对照：广东台正常播放 1280×720，央视频正常播放 1920×1080。模拟广东台原生媒体错误后，HLS.js 使用网站当前地址恢复真实流到 1280×720、readyState 4。此结果不能替代 Android16 手机验证。
- 71 项 Android 播放断言，包含新增注入重试上限、旧回调隔离、诊断采集；45 项自动切源断言。
- 32 项 HLS 恢复、17 项网站兼容与诊断、56 项媒体健康检查的 Node 断言。
- 原生超时可取消尚未开始的兼容恢复，并销毁已运行的恢复播放器。
- 正式包已在 MuMu 覆盖安装，广东分组的广东卫视全屏出画；最低 API28、手机/电视启动入口、版本号与既有 v3 签名证书核验通过。安装包大小 780404 字节。

另观察到广东珠江的旧备用来源跳转后未提供视频；本版未调整该备用来源，也未把它算作播放成功。频道配置继续从用户仓库更新。

## 安装和手机回测

版本 0.4.14 / versionCode 22，最低 Android9（API28），使用既有正式签名，可覆盖安装并保留配置。通用包支持 ARMv8 手机；ARMv7 下载文件与通用包字节相同，便于电视盒子选择。Android9 ARMv7 真机仍待验证。

请在 realme GT5 覆盖安装后分别回测广东卫视、广东珠江的 m.gdtv.cn 和央视频来源。如仍失败，可打开「更多 → 来源详情 → 复制播放诊断」，把文本发回继续定位，无需先连接 USB。北京台网页登录限制属于已观察到的网站要求。
