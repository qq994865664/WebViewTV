# WebView电视 0.4.4

当前直播源未能开始播放或持续卡顿时，自动尝试下一个直播源。

## 设置

进入「设置 → 播放 → 播放超时自动切源」，可选择：**关闭、5 秒、10 秒、15 秒、30 秒**。点击「保存并返回」后生效。默认 15 秒；旧配置未包含此项时也使用 15 秒。

本地 JSON 对应 `playback.sourceTimeoutSeconds`，0 表示关闭。例如：

```json
"playback": {
  "fastSwitch": true,
  "rememberSource": true,
  "sourceTimeoutSeconds": 15
}
```

配置导入和校验拒绝其他数值及字符串。仓库频道更新仍只更新 `channels`，不会覆盖本机的超时时间。

## 行为

- 从加载该源开始计时；解码首帧和实际视频时间推进会重置等待时间，网页加载完成及视频元数据本身不算播放成功。
- 开始播放后仍监测持续卡顿。计时采用单调时钟，500ms 检查一次；JS 每秒采样视频状态。切换发生在达到所选时限后的检查点。
- 当前频道的来源按顺序循环查找未尝试项，同一轮连续故障每个源只试一次。全部失败后停止并提示；单源频道只提示无备用源。
- 手动换台、切源和刷新开始新一轮尝试；实际播放恢复后，后续卡顿可再次尝试其他来源。
- 菜单、设置、节目单、窗口失焦和普通后台暂停计时；恢复后给予新的等待时间。旧页面的 token 不会干扰新频道。
- 自动切换复用既有播放逻辑和来源记忆。页面无法向原生层报告播放进展时，可能被视作超时；遇到此类网站可延长时限或关闭功能。

## 验证

2026-10-13，MuMu Android15：

- 独立测试包运行生产 `MainActivity`、配置仓库及设置，**40 项断言通过**。模拟三个失效地址，验证 5 秒后顺序切源、所有失败后停止、旧 token 无效、正常进展不切源、面板暂停、恢复后等待、后续卡顿切源及设置关闭。
- 通过模拟单调时钟验证 5/10/15/30 秒边界、末尾回到首个可用候选、单源、手动重试及恢复后的新故障。
- 配置测试覆盖所有选项保存、旧配置默认值、非法值拒绝；实际设置选择「关闭」并保存后不再自动切源。
- `tests/playback-health.test.js` **16 项断言通过**：静止、暂停、缓冲、错误、结束、视频替换、移除与恢复、页面退出等检测。
- 正式包覆盖安装后检查设置和下拉选项。签名、APK 资源及两个公开配置文件校验通过。
- 正式包以默认 15 秒设置正常播放 CCTV-1，关闭菜单连续观察 25 秒，仍保持来源 2/3，没有误切源。
- 测试使用独立包名和虚构频道，不替换正式应用频道。测试包已卸载。运行实测为 MuMu Android15，未新增 Android9 或 ARMv8 真机测试。
