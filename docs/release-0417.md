# WebView电视 0.4.17

修复真实播放进度反馈较慢时，直播仍被判定为“本轮等待已达 60 秒”的计时缺陷。

## 原因与修改

旧逻辑把“播放稳定后清空失败来源记录”与“重置本轮等待计时”绑在一起。相邻有效播放反馈间隔超过 2.5 秒时，稳定性计时反复重启，60 秒总计时却一直保留；即使每次反馈都早于用户设置的单源超时，也会在 60 秒误报失败并停止播放器。

新逻辑在每次有效媒体播放进度到达时重置等待起点。失败来源记录仍需连续稳定播放后才清空，避免偶尔出一帧就反复尝试已经失败的来源。网络请求、缓冲区增长、网页加载完成和旧页面回调仍不能延长播放期限。

真正没有播放进度时，继续遵循 5/10/15/30 秒切源、每轮最长 60 秒、关闭自动切源时等待 18 秒的规则。

## 验证

- 确定性测试在旧代码上复现：每三秒提供一次真实播放进度，第 60 秒仍返回等待超时。
- 修复后通过 627 项看门狗断言，覆盖各超时选项、持续三分钟的稀疏播放反馈、后续真实卡顿、跨源累计期限、短暂恢复及后台暂停。
- MuMu Android15 通过 48 项切源回归，覆盖真实 MainActivity 桥接收到稀疏播放反馈后不显示错误卡、不误切源，以及真实故障切源、旧页面隔离与设置持久化。
- 正式 APK 资源校验及 v3 签名验证通过。

盒子具体型号与 WebView 版本尚待补充，因此这是对已复现计时缺陷的修复，不等于已在用户盒子实机验证。
